# Member Frontend Languages

The member application supports Thai (`th`, default), English (`en`) and
Simplified Chinese (`zh`). AdminConsole is outside this localization scope.

## Implementation

- `lib/i18n/index.ts` configures i18next and react-i18next with bundled resources.
- `lib/i18n/messages.ts` and `additional-messages.ts` contain rows of source key,
  English, Chinese and an optional Thai override for non-Thai source keys.
- Render UI strings with `t(key, values)`. Keep interpolation placeholders identical
  in all translations. React renders the result as text, not HTML.
- Use `localeTag()` for date/number display. Booking API dates, IDs, prices and
  status codes remain canonical and independent of display language.
- `LanguageSwitcher` uses a keyboard-accessible native select. The validated
  language preference is stored under `ppa.locale`; unavailable storage is tolerated.
- The server renders Thai. Client effects restore the saved preference after
  hydration and update the document language. Switching does not remount the
  booking application or discard its selection.

## Managed Content

Known default content has dictionary translations. New operator-written content
can carry translations in its existing `metadata` field, without a schema change:

```json
{
  "i18n": {
    "en": { "title": "Club news", "body": "New opening hours" },
    "zh": { "title": "俱乐部资讯", "body": "新营业时间" }
  }
}
```

Only `title`, `subtitle`, `body`, `actionLabel`, `name` and `description` may be
overridden. IDs, prices, routes and permissions cannot be changed by translations.
Missing or malformed translations fall back to the original content. Arbitrary
operator text, member names and stored booking titles are not automatically
machine-translated. This change does not add an AdminConsole translation editor.

## Verification

- `npm test`: catalog completeness, duplicate keys, placeholder parity, locale
  validation, metadata field restrictions and untranslated static Thai JSX checks.
- `node scripts/responsive-check.mjs`: 285 fixture views, including 20 member
  screens in all three languages at 320, 768 and 1440 pixels; language persistence,
  layout overflow and retained booking selections. Fixtures are not proof of a
  completed live payment or a production booking.
- `npm run lint` and `npm run build`: static checks and production compilation.
